## 3. Revisión individual

La consola agrupa **cinco reglas WARN y 63 PASS**. El JSON desglosa siete grupos:
**uno medio, tres bajos y tres informativos; ninguno alto**. No se confunden reglas,
grupos, instancias ni avisos informativos con siete vulnerabilidades explotables.

| Regla / hallazgo | Evidencia y análisis | Tratamiento en este PR / cierre pendiente |
|---|---|---|
| **10055 · CSP style-src unsafe-inline**, medio, confianza alta | Presente en raíz y fallbacks; la política efectivamente permite estilos embebidos arbitrarios | Retirar `unsafe-inline` de Spring/Nginx/Caddy. React usa CSSOM desde scripts propios; se prueba que sigue funcionando. Swagger necesita el estilo estático de su logo: se autoriza **solo su SHA-256**, no estilos arbitrarios. Falta revalidación pública tras CD |
| **90004 · COEP ausente**, bajo | Tres documentos sin `Cross-Origin-Embedder-Policy` | Añadir `require-corp` a API/HTML/errores. La aplicación carga recursos propios; cambios futuros a proveedores externos requieren revisar CORP/CORS. Falta revalidación pública |
| **90004 · COOP ausente**, bajo | Tres documentos sin `Cross-Origin-Opener-Policy` | Añadir `same-origin`; no hay OAuth/popups externos en el flujo actual. Falta revalidación pública |
| **90004 · CORP ausente**, bajo | Cuatro instancias, incluido CSS propio | Añadir `same-origin`; mantener Nginx sin duplicar cabeceras de Spring y Caddy reemplazando las del upstream. Falta revalidación pública |
| **10015 · Revisar Cache-Control**, informativo | El propio reporte identifica `no-store`, no una respuesta privada que se haya cacheado | Mantener `no-store`. No se quita una protección para silenciar el aviso. Revisión final con el equipo; no se declara un cambio inexistente |

| **10109 · Modern Web Application**, informativo | No encuentra enlaces HTML navegables pese al bundle JS | Limitación real del spider tradicional. No se oculta: la cobertura autenticada requiere cuentas/recorrido controlado y no está acreditada por este baseline |

El hash CSP corresponde exactamente a:

```css
.logo_small_svg__cls-2{fill:#fff}.logo_small_svg__cls-3{fill:#85ea2d}
```

Se comprobó que sale de `swagger-ui-standalone-preset.js` 5.34.1. Una primera política
sin ese hash bloqueó el SVG de Swagger en el navegador; se corrigió **sin volver a
habilitar unsafe-inline**. `SwaggerSeguridadTest` vincula contenido y hash. No es una
credencial hardcodeada ni una autorización genérica de CSS. Al actualizar Swagger,
se debe revisar el estilo y repetir pruebas; no agregar hashes por ensayo ciego.
